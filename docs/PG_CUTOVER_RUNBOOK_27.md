# PostgreSQL cutover and rollback — operator draft, not an executed migration

1. Obtain separate written authorization and a disposable PostgreSQL 16+ environment. Never point the rehearsal runner at production. Configure `PGHOST=127.0.0.1`, `PGDATABASE=sa_disposable_ci`, a non-superuser test role, and `SA_PG_DISPOSABLE=YES_I_ACCEPT_DATA_LOSS`.
2. Run `node scripts/pg-migrations.js --check`, `--apply`, `--verify`; inspect ledger checksums, PostgreSQL logs, constraints, indexes and trigger behavior. The runner refuses remote hosts and production-looking database names. It does not create databases.
3. Export only synthetic catalog data with `node scripts/export-catalog-pg.js /private/catalog-export`; verify with `node scripts/pg-catalog-integrity.js /private/catalog-export`; generate the reviewed import SQL. Run on disposable PostgreSQL and compare every row and relationship. The export must not include accounts, sessions or private evidence.
4. If a private account snapshot is explicitly approved, set `SA_PG_SNAPSHOT_APPROVED=YES_PRIVATE_BACKUP` and a strong key in a protected environment, then run `node scripts/pg-private-snapshot.js export /private/snapshot.json --sqlite /private/source.db`. Verify using `verify`; do not log the key, decrypt into a public directory or place snapshots in Git/ZIP. This is **not** an import tool, production backup or complete MFA/session migration.
5. Complete Node-vs-Spring behavioral parity for authenticated and denied paths; independently verify ownership, consent/age gates, holds, revocation and territory restrictions. Current Spring module is intentionally read-only and loopback-only.
6. Plan a maintenance window with read-only freeze or tested CDC/shadow reads, reconcile counts and high-water marks, prepare rollback to a point-in-time snapshot, and record an operator-approved cutover decision. Do not dual-write secrets or send unapproved real data to test environments.
7. After explicit cloud authorization, prove managed DB encryption, PITR, backup retention, restoration to a **separate** environment, monitoring, alerting and cost budgets. Rehearse failback with media/catalog parity and account security checks.

**Rollback for migration 013:** `migrations/postgresql/rollback/013_integrity_and_audit.rollback.sql` is manual disposable-only DDL; it intentionally does not rewrite the migration ledger. For earlier schema changes or a real cutover, restore an approved consistent snapshot and reconcile application versions; never assume DOWN SQL can undo destructive changes or protect account secrets.

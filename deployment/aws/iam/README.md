# G02 IAM and cost controls — review plan only, NOT deployed

No AWS credentials, resource identifiers, secrets, KMS keys, policies or IAM roles have been created or modified. Before staging, an account owner and the provider must authorize the exact workload and expected charges. Use distinct least-privilege roles: CI OIDC (artifact publishing only), application (read permitted metadata and request authorized signed playback; no S3 original read), transcoder (read originals and write only rendition prefix), and CDN origin access control (read rendition objects only with matching distribution ARN). Require scoped KMS permissions, Secrets Manager rotation and audited break-glass access. Deny public S3 ACL/policies, long-lived IAM user access keys, and wildcard resource permissions unless independently reviewed.

Enable cost budgets and alerts before any resource creation; review S3 storage, CDN egress, transcoding, logs, WAF and database charges. Domain, TLS, provider, privacy and content-rights approvals are separate mandatory gates. The evidence template in `docs/AWS_GATE_EVIDENCE_TEMPLATE.json` is a checklist only: a filled reference is not independent verification or deployment authorization.
